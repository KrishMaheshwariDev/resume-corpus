- Type: Big data / AWS / Spark / Terraform / data engineering
- Dataset: NYC/NYU taxi data, 8GB+

### Summary

Event-driven big data pipeline that ingests NYC taxi CSV files, processes them with Spark Structured Streaming, persists analytics data to PostgreSQL/RDS, and supports analysis/BI or Flask/Plotly visualization.

### AWS architecture

- S3 incoming bucket
- S3 ObjectCreated event notification
- Lambda ingestion function
- EFS filesystem and access point
- ECS Fargate Spark service
- RDS PostgreSQL
- CloudWatch Logs
- VPC
- Public and private subnets
- NAT Gateway
- Internet Gateway
- Security groups
- IAM permissions
- Terraform-managed infrastructure

### Data flow

- CSV lands in S3.
- S3 ObjectCreated event triggers Lambda.
- Lambda stages the file into EFS using `.part -> .csv` atomic rename.
- Spark Structured Streaming running on ECS watches EFS.
- Spark processes new files in micro-batches.
- Results are written to PostgreSQL/RDS using JDBC.
- EFS checkpoints preserve streaming continuity.

### Local architecture from portfolio

- Docker Compose for Spark, PostgreSQL, and Flask.
- Flask endpoints backed by SQL and Plotly visualizations.
- Containerized Spark and Flask components.
